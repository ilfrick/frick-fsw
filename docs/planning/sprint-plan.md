This document turns the milestone roadmap into an **ordered sprint plan** that
finishes every development in the roadmap. It is the execution view of
`docs/roadmap.md` / `docs/development-plan.md`; it is kept current per norm **N8**
and re-baselined at every loop start per norm **N19**. Sprint = 2 weeks
(10 working days); effort figures are indicative (the project is executed by an
AI agent under human approval, so calendar time is dominated by review loops,
not by wall-clock).

**N21 sequencing rule:** prioritize and correct functional issues affecting
correct/intended software behavior, and implement missing features committed
for the current or previous sprints. Non-functional findings are tracked as open
NCs for later review/disposition and do not stop unrelated development. This
does not close NCs or waive separate commit/release/safety/security gates.
**N22 test rule:** requirement-based and integration testing includes nominal
and applicable out-of-bound cases with explicit expected-result comparisons.
Renode is an emulator that can host integration tests, not a test type.

**Reconciliation rule:** the checked-in implementation and executable evidence
are the as-is source of truth; the sprint plan must enumerate all roadmap scope,
and roadmap/development-plan status may say “delivered” only for implemented,
tested scope. Review, target-hardware, emulator-fidelity, and authority gaps stay
separately visible and do not get erased by a green host test. If an earlier
record cites an absent NC, first reconcile it against the repository's actual NC
register; do not invent a phantom `NC-EXT-*` reference. Allocate a new named NC
only for a distinct residual, and keep the `NC-EXT-*` sequence contiguous with
the highest existing record (currently NC-EXT-82).

## 1. Priorities (owner direction recorded)

1. **License status:** owner authorization for original project-authored code
   and materials is recorded and applied. NC-EXT-43 remains for external/
   generated component boundaries and combined-distribution compatibility; it
   is not pending owner authorization and does not stop unrelated development.
2. An earlier owner directive says **Drivers first** — finish the M4/M11 HAL
   reference classes before other work.
3. The later proposed sequence is **S8-FU review closure → S8-VV-FU** for
   bounded test gaps → **S8-PUS-FU** for independently reported,
   project-correctable PUS defects → **S8-SCH** (OBJ-31/M17: RTEMS-backed,
   table-driven SB dispatcher) → **M12** (integrate an OBCP engine) → **M16**
   (in-house OBCP engine development) → **M13** (reference mission services).
4. **Owner instruction and plan interpretation (2026-10-15):** the project owner
   instructed, “resume the sprint plan with the next sprint as planned.” Because
   the corrective sequence above lists **S8-FU** first, this plan interprets
   that instruction as selecting S8-FU ahead of competing “drivers first”
   sequencing. This is the plan's interpretation, not an explicit owner quote
   naming S8-FU. Remaining driver work stays tracked and may proceed when it does
   not conflict with this sequence. This records execution order only; it does
   not approve requirements, risk, or release. R4 review FRICK-REVIEW-0311
   accepted this bounded interpretation; NC-EXT-30/65 are closed for this
   documentation issue only.
 5. **ECSS Category B is the project target, not a confirmed mission assignment**;
   classification and tailoring require program authority. Class-A gaps remain
   documented per norm **N5**; no class-A claim is made.
 6. **Tools**: open-source or free, preferably with space/aerospace heritage.
 6. **M14** after all other milestones; **M15** after **M14**.

Everything is delivered through the same non-derogable cycle (norm N15): full
build/test/Lean/trace/format gates → functional validation in **Renode** (norm
N18) → independent reviews (R1/R2/R3/R4 as applicable) → **Senior SW PA** review
(norm N20) → commit + push to both remotes (norm N7). Before loop closure,
resolve functional findings and findings that block an applicable gate; track
other non-functional findings as open NCs with owner and disposition under N21.
Deferral does not close an NC or waive any applicable review, commit, release,
safety, security, or contractual gate.
