## 4. Verification results

### 4.1 Prior F-002 (S6 wire profile) — RESOLVED

ICD rev 1.3 line 111 now reads:

> `| 6 | 5 / 6 | memory dump (TC 6,5 -> TM 6,6) | TC/TM | memory dump … (region id[1] + byte offset[4 BE] + length[2 BE], 7-octet TC payload); length bounded by the registered region and FF_PUS_MAX_TM_FRAME |`

Implementation `svc6_dump` (`src/pus/pus_services.c:343–370`):

```
343  static FF_Status_t svc6_dump(…)
346      if (len != 7u) { return FF_BAD_SIZE; }
349      uint8_t  region_id = d[0];
350      uint32_t offset    = rd_u32(&d[1]);      /* big-endian, l.77 */
351      uint16_t size      = rd_u16(&d[5]);      /* big-endian, l.73 */
352      if ((region_id == 0u) || (size == 0u) || (size > FF_PUS_MAX_TM_FRAME)) return FF_BAD_SIZE;
363      if ((offset <= region->size) && ((uint32_t)size <= (g_mem_regions[i].size - offset)))
366          return FF_PusSendTm(FF_PUS_SERVICE_MEMORY, 6u, src, size);
369      return FF_ERROR;
```

Derived wire layout: `region_id:u8 | byte_offset:u32 BE | length:u16 BE` = 7 octets,
`region_id != 0`, `length != 0`, `length ≤ 1024`, `offset <= region_size`,
`length <= region_size − offset`, pointer never on the wire. This is byte-for-byte
what the ICD now states for TC[6,5]; the constraint wording is accurate.
`FF_PusRegisterMemoryRegion` is the region-registration equivalent cited
(`:184`, 8 regions, l.28). **No residual TC mismatch.**

### 4.2.1 Behaviour independently verified against the ICD/TS-1 text

- **TC[3,2] is not a housekeeping command and is refused.** `(3,2)` is not in the
  registration table (`pus_services.c:517–518`); `FF_PusIngest` (`pus.c:243–256`)
  returns `FF_NOT_FOUND` with an unknown-subservice S1 completion failure when the
  completion-ack flag is set (`FF_PUS_FAIL_UNKNOWN_SUBSERVICE`, `pus.c:252`).
  `tests/unit/test_pus_fu.c:374` asserts `send_hk_id_tc(2u, 33u) == FF_NOT_FOUND`.
  The TS-1 sentence "TC[3,2] … is rejected as unsupported" is accurate.
  Independently checked against the standard: ECSS-E-ST-70-41C **TC[3,2] = create a
  diagnostic parameter report structure** (§8.3.2.2), i.e. it is a different
  function, so refusing it is ECSS-consistent and not an arbitrary exclusion.
- **TC[3,27] is one-shot and independent of periodic state.** `svc3_report`
  (`pus_services.c:278–339`) never reads `g_hk_reports[].enabled`; the only
  reference is the comment at l.301–302. The test performs disable (l.376) →
  request → asserts TM(3,25) (l.378–379), then enable (l.381) → request → TM(3,25)
  (l.383–384): confirms the ICD cell "one-shot; no periodic arming".
- **TM[3,25] content = report id + provider data** (l.313, 327), matching ICD l.108.
