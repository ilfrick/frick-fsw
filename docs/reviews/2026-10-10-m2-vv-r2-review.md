## 4. Findings

| # | Severity | Item / Requirement | Finding | Evidence | Recommendation |

| 1 | **Major** | `tests/unit/test_time.c` (ctest `time`); SRS-REQ-021..024, SSS-REQ-016 | **The M2 unit suite never executes.** `test_time.c` defines `int main(void) { FF_TEST_MAIN(...); return 0; }` while `FF_TEST_MAIN` expands to a full `int main(void){...}`. The expansion therefore becomes a **nested, never-called `main`** and the real entry point is an empty function that always returns 0. None of the 7 test functions run and the suite can never fail. The recorded `ctest PASS (5/5)` and `test_time PASS` (verification-results.md M2 row) are **vacuous**; the Tst method evidence for SRS-REQ-021..024, SSS-REQ-016 (and SRS-REQ-010/SSS-REQ-007 CUC links) is **invalid** (ECSS-E-ST-40C requirement coverage; norm N11 record integrity). | • The 4 other suites use file-scope `FF_TEST_MAIN(...)` (test_sb.c:68 etc.); only `test_time.c` wraps it in an outer `main`. • `objdump -d .../test_time`: `main` = `endbr64; xor %eax,%eax; ret`; the 7 test functions exist but are never referenced. • `strace -f -e trace=write`: **0** `write(` syscalls (a real harness run prints a summary). • Fresh recompile of the committed source shows the same vacuous `main`. • Coverage corroborates: total lines grew 1095 -> 1310 for M2 while covered lines grew 571 -> 579 (+8) - the ~215 added time/pps lines are effectively unexecuted. | Replace the wrapper with file-scope `FF_TEST_MAIN(test_init_and_basic_cuc, ..., test_pps_backend);` exactly as the other suites (delete the outer `main` and `return 0;`). Re-run every suite; then correct the test logic per F2/F5; regenerate coverage + metrics; re-record the genuine `5/5` result in verification-results.md (norm N11/N15). |
