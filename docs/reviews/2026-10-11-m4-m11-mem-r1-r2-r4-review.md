## 1. Scope

Reviewed the third M4-residual / M11 increment (reference static RAM pool +
reference DMA helper) under three independent profiles:

- **R1 (design/code)**: the `FF_MemPool_t` bump allocator of `ff_mem_static.c`
  (bounded, heap-free, 8-byte alignment, integer-overflow-safe exhaustion path
  `n > limit - aligned`, `alloc(0)`, `reset`, non-overlap) and the single-instance
  static binding; the reference `FF_Dma_t` (identity virtual<->physical
  translation on the U54, no-op cache hooks) against `hal_mem.h` (which requires
  RISC-V "cache maintenance") and against the reference GEM driver's injected
  `FF_Dma_t` usage.
- **R2 (V&V)**: independence and oracle strength of `tests/unit/test_mem.c`,
  validity of the Renode emulated-DDR/DMA check folded into `RENODE_TEST: PASS`,
  and the resulting requirement evidence (SRS-REQ-049); requirement clarity,
  parentage (`SSS-REQ-020`) and traceability convergence.
- **R4 (documentation, N17)**: README driver inventory, verification-results,
  renode-environment, tool-qualification, handover, CHANGELOG consistency;
  counts/revisions/history; over-claim / honesty (software HAL class over the
  emulated DDR only; no-op DMA cache hooks = seam; real silicon = GAP-A5).

Allocator analysis (R1):

- Exhaustion path is integer-overflow safe: the `aligned > limit` guard executes
  before `n > (limit - aligned)`, so the subtraction cannot underflow, and the
  subsequent `aligned + n` cannot overflow because `n <= limit - aligned`
  (`ff_mem_static.c:24-32`). Correct idiom.
- `reset` restores `cur = base`, `used = 0`, and the region is reusable
  (`ff_mem_static.c:35-41`); `alloc` correctly rejects `n == 0` and an unbound
  pool; `used` is cast to `uint32_t` only after the `n` bound check, so it cannot
  wrap (`size` is `uint32_t`).
- Identity `virt_to_phys`/`phys_to_virt` is a valid assumption for this build:
  `config/rtems/rtems_config.c` sets up no MMU/paging, so the U54 runs with
  translation off (physical addressing).

### Positive evidence

- The pool is bounded, heap-free, 8-byte aligned, non-overlapping and returns
  `NULL` on exhaustion without integer overflow; `alloc(0)`/unbound/`reset` are
  handled; the `FF_MemPool_t` vtable (`alloc`, `reset`) and metadata
  (`name`/`base`/`total`/`used`) are complete. The single-instance static binding

## 4. Conclusion

- **R1 (design/code)**: **APPROVED WITH COMMENTS**. The allocator is correct and
  the exhaustion path is integer-overflow safe; the single-instance model is
  documented. The reference `FF_Dma_t` identity translation is valid for this
  build (no MMU configured), and the no-op cache hooks are labelled a "seam" in
  the code - but the requirement/docs do not yet tie the unmet RISC-V cache
  obligation to GAP-A5 (R1-01, Minor). `alloc(0)` semantics and the
  single-instance/non-reentrancy consequences are undocumented (Comments).
- **R2 (V&V)**: **APPROVED WITH COMMENTS**. The host test is independent and
  green (14/14, `test_mem` 20 checks) and the trace gate converges; the Renode
  functional result reproduces (`hal_mem=PASS`, `RENODE_TEST: PASS`). The
  emulated "DDR/DMA" check is weaker than the CHANGELOG/records imply (R2-01,
  Minor) and the alignment oracle is self-referential (R2-02, Minor); `make
  renode` is not reproducible on this ZFS host due to Renode's `CreateFileBackend`
  on the bind mount (R2-03, Comment, pre-existing and not caused by this change).
- **R4 (documentation, N17)**: **APPROVED WITH COMMENTS**. Counts, revisions and
  histories are consistent and the README panel was regenerated; but the
  renode-environment prose and the handover status line are stale for SERIAL/MEM
  (R4-01/R4-02, Minor, recurrences from FRICK-REVIEW-0043), the handover commit
  reference and review list are out of date (R4-03, Minor), the DMA-cache
  GAP-A5 linkage is not stated (R4-05, Minor), and the recurring trailing-newline
  (R4-04), CHANGELOG over-claim (R4-06) and review-log (R4-07) items remain.

**Overall**: **APPROVED WITH COMMENTS** - no Major findings. The increment is a
correct, bounded, heap-free reference pool plus a clearly-labelled reference DMA
helper, verified by an independent host test and reproduced in Renode. The Minor
findings (DMA-cache/GAP-A5 documentation, Renode-check over-claim, self-referential
alignment oracle, stale renode-environment/handover prose) must be corrected or
justified and tracked to closure (norm N12) before the change is considered
closed.
