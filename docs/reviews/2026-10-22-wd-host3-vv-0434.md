## 1. Oracle audit, case by case (as reviewed)

Structural finding qualifying every verdict: for the *state* observables the actor and the
oracle are the same artefact (the fixture). The **independent** elements are (i) the
**unchanged production PAL** (`src/core/pal/pal_watchdog.c:39-98`) and (ii) the
**read-back-derived** feed outcome in the double, which compares the counter with the
`TIME` register *after* the write instead of trusting the model's write decision. That is
the correct anti-"success-programmed mock" construction.

| Case | Discriminating observable | Satisfiable by a mock that merely returns the expected value? | Healthy control load-bearing? |
|---|---|---|---|
| **HM-P1** lock | register read-back of `TIME`/`TRIGGER`, observer disposition, observer pre/post state, model lock flag | **No** — the primary observable is *state*; a double always returning `FF_SUCCESS` would leave the written values in place and fail the read-back | **Yes** — the "not yet configured" leg requires read-back 500 and disposition `APPLIED`; the applied-configuration leg is the control |
| **HM-P2** window | counter read-back (no reload / reload), forbidden status, timeout interrupt, disposition, production feed counter | **No** — "counter still 950" is only reachable by *not* reloading | **Yes** — the below-`MSVP` leg and the window-disabled leg both fail if the model refuses unconditionally |
| **HM-P3** gating/clock | counter across an explicit tick advance, clock-running flag, feed counter, disposition | **No** — a frozen counter across a tick advance is a physical consequence, not a return value | **Yes** — the ungated leg fails if the model refuses permanently |
| **HM-P4** wrong-key class | counter unchanged at 950, `GetFeeds()==0`, disposition `refused-key` ×3 | **No** — the counter is pinned at a value ≠ the reload value | n/a (negative case); the complementary healthy control is HM-P5, and both pass in the nominal run |
| **HM-P5** documented key | counter reload read-back, feed status, `GetFeeds()==1`, disposition `applied` | **No** — requires the counter to *become* 1000 from 950 | n/a (positive case); its discriminating role is confirmed by MUT-4 |
| **HM-P6** observer order | matched-subsequence count, write count | n/a by design — declared a harness-capability self-check, **not** HS-P5 and **not** NC-3 evidence | n/a; killed by MUT-5, so not vacuous |

**Anti-vacuity constraint: satisfied.** Every negative leg asserts at least one *state*
observable besides the status token, plus the exact token; every expected value is a
literal constant or a boolean truth; **no assertion compares one model-derived value with
another**.

## 2. Reload-observable discipline (the "advance the counter first" condition)

**Satisfied in substance.** The reload value is `TIME` = 1000. Every assertion that
discriminates a reload from a non-reload is issued from a counter value ≠ 1000
(950, 890, 901, 940) and is compared against the pre-write value. **No positive reload
assertion is issued at a counter value equal to the reload value**, and every negative
assertion is preceded by an assertion of the pre-write value. Two *auxiliary* initial-state
observations assert the counter **at** the reload value right after initialisation; they
are not reload/no-reload discriminations, and the addendum's blanket sentence overstates
the case → **D2**.

## 3. Wrong-key class (the NC-EXT-205 residual)

**Satisfied.** Three distinct wrong-key values (`0x00000001`, `0xDEADC0DF`, `0xFFFFFFFF`),
each non-zero and ≠ the documented key. **Kill demonstrated, not asserted:** the retained
MUT-4c raw log shows the failure multiplicity ×4 on the four HM-P4 assertion lines = 2
executions × **2 of the 3 wrong keys** wrongly reloaded (the exempted value is
`0x00000001`). A single-value stimulus would have survived exactly this mutant. The
residual is closed **in the model scope only**, and the addendum says so in three places;
the NC register file is byte-unchanged and no NC status/owner/severity was altered.
