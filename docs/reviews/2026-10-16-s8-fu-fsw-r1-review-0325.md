## Findings

1. **P2 — UART busy-spin on disconnected terminal.** `link_uart.c` treated every
   zero-byte `read()` as a VTIME expiry and retried until the caller deadline.
   A disconnected PTY can return zero immediately, causing CPU-consuming retries
   in the command-ingest receive path. Distinguish a substantially early zero
   return from a decisecond timeout and add a disconnected-PTY regression case.
2. **P2 — Malformed plausible PDL can consume a following valid TC.** The UART
   framer trusts an in-range PDL until the declared length is accumulated. A
   malformed candidate whose declared payload overlaps a following valid TC can
   deliver a combined candidate downstream and lose the inner valid frame. No
   approved recovery policy is available; do not introduce an unapproved
   inner-boundary heuristic. Obtain system/RTOS authority disposition and define
   recovery/partial-discard semantics before changing this behavior.
3. **P2 — Shared predictable PTY path.** The host test unlinked and recreated a
   fixed `/tmp/frick-fsw-uart-test` symlink. Concurrent runs can interfere and
   the path has avoidable filesystem-race exposure. Use a unique per-run
   temporary directory/path and cleanup.

## Bounded observations

The CCSDS decoder source has no delta in this candidate; its current length
checks and output-preservation tests were reviewed as background. The `link_ip`,
`link_tsn`, and TSN-test changes are formatting-only according to the diff.
Host results do not establish RTEMS runtime behavior. The review does not define
mission/profile policy, approve timeout tolerances, close NC-EXT-07, or approve
release.
