## 3. Coverage and adequacy assessment

### 3.1 What the QEMU check establishes

The QEMU leg runs the **generic `riscv/rv64imafdc` RTEMS BSP** image (built via
`cmake/toolchains/rtems-riscv-generic.cmake`) on `qemu-system-riscv64 -M virt
-bios <elf>`. The retained console demonstrates, at the level of a boot/bring-up
smoke check:

- RTEMS boot into the entry point and the RTEMS/PAL startup;
- `POSIX_Init` → `ff_fsw_main` bridge and framework bring-up;
- registration/start of the six applications (`CMD_INGEST`, `TM_OUTPUT`,
  `SCHEDULER`, `HK`, `HS`, `SAMPLE`);
- steady-state TM emission over the loopback link (`TM -> link, NN bytes`).

This is a **meaningful, honestly-scoped** increment: it exercises the real RTEMS
target binary (not the host POSIX simulator) on an emulated RISC-V machine and is
documented as a partial mitigation of GAP-A5.

### 3.2 What it does not establish (correctly declared)

`emulated-target.md` §3/§4 correctly bound the claim: **no MPFS peripherals**
(UART/GEM/CAN/SPI/I2C/GPIO/QSPI/eNVM driver behaviour), no fabric IP, no real
silicon (electrical/radiation/errata/exact timing), no WCET/stack. The
`lean_note` for SRS-REQ-043 likewise states the real-silicon residual is GAP-A5.
The Renode leg (`polarfire-soc`) remains the peripheral-bound functional path.
The scope split is adequate and not overclaimed at the requirement/design level.

### 3.3 `qemu_vv.sh` script adequacy

Assessed positively on the core mechanics:

- **SKIP vs FAIL semantics:** correct and honest. SKIP (exit 0) when the
  generic-BSP ELF is absent or when no QEMU runtime exists; **FAIL (exit 1)** when
  the ELF is present and the banner markers are absent. A recorded SKIP is not
  passed off as a PASS.
- **Bounding:** `timeout 20` wraps the QEMU process; `-nographic` + headless
  input make it non-interactive; the script cannot hang on QEMU itself.
- **Marker robustness:** `grep -aq` treats the console as text and tolerates
  ANSI/control characters; the two fixed markers (`frick-fsw`,
  `applications registered`) both match the retained console. `bash -n` clean.
- **Console retention:** the raw log is copied to a fixed path
  (`build/rtems-generic/qemu-console.log`). See R2-03 for the retention caveat.
- **Exit codes:** explicit `exit 0`/`exit 1` on all branches; `set -uo pipefail`.

Adequacy of the *claim* supported by the marker is weaker than the register's
wording (R2-04); a hang after registration would still PASS. This is acceptable
for a boot/bring-up smoke check but must not be read as functional validation.

**Verdict: REJECTED** (R2-01 Major).

The QEMU check itself is a sound, honestly-scoped boot/bring-up verification and
the SKIP/FAIL/timeout/ANSI mechanics are adequate. The rejection is driven by an
**evidence/qualification overclaim**: T20 is registered QUALIFIED and mapped to
`` `ci:emulated-run` `` although no CI job exercises `qemu_vv.sh`, so its
qualification basis and the mapping are inaccurate for the applicable class-B
criticality. R2-02..R2-07 are Minor/Comment and should be dispositioned in the
same N12 closure cycle. No safety-barrier defect was found.
