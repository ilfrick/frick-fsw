# FRICK-REVIEW-0423 — NC-EXT-199 N18 Renode runner correction (V&V)

**Profile:** R2 / V&V, fresh independent context  
**Disposition:** Review evidence only. No edits, no NC closure, no gate pass, no
testware qualification, no target WCET claim, and no watchdog/report-policy
decision.

**Scope:** `tools/scripts/renode_vv.sh` (corrected), the new verdict unit
`tools/scripts/renode_vv_verdict.sh`, the new regression test
`tests/shell/test_renode_vv_verdict.sh`, the CTest registration in
`tests/CMakeLists.txt`, and the retained evidence of 2026-10-20/2026-10-21.

## Bottom line

**The false-PASS mechanism is closed**, at the runner level and by construction
in the verdict unit, and the regression cases are discriminating — proven by
execution and by mutation, not only by inspection.

| Question | Answer |
|---|---|
| Can a stale or foreign run still produce PASS? | **No.** Every read is confined to a fresh per-run directory; the historical fixed paths are never read. |
| Does it fail closed? | **Yes** — missing, unreadable or empty capture, a failed run-directory creation, a failed container start and a failed capture all produce FAIL (exit 1), never PASS or SKIP. |
| Do true statuses survive? | **Yes** — container status, container exit code and the bounded-wait outcome are captured without a pipeline and reported in the verdict line. |
| Are the regression cases meaningful? | **Yes** — mutation-proven: reintroducing the stale fixed-path read, deleting the fail-closed block, or turning a marker-absent case into PASS each makes the test fail. |
| New defects introduced? | **1 Major, 3 Minor, 6 Low/Observation**, all recorded below; the Major and the three Minor were corrected in the follow-up round. |

## Verified by execution

- **Confinement:** two consecutive runs, the first carrying the marker and the
  second without it, produce PASS then FAIL; the second never sees the first
  run's artefacts.
- **Fail-closed paths, each injected and executed:** run-directory creation
  failure, `docker run` failure, `docker logs` capture failure, `docker cp`
  console failure, missing capture, unreadable capture, empty capture — all
  exit 1 with a specific reason. The verdict unit never returns SKIP; its only
  other exit code is 2 (usage), unreachable from the runner.
- **Statuses:** `status.env` records `CONTAINER_STATUS=exited`,
  `CONTAINER_EXIT=0`, `WAIT_RESULT=exited`; the verdict line reports them. A
  run whose container never exits ends after the bounded window (121 s
  measured) with the timeout FAIL reason — no hang.
- **Classification:** the marker check precedes the fatal scan, so a
  marker-bearing run is never demoted; the recorded 2026-10-20 success fixture
  contains **zero** occurrences of all six fatal patterns, so the
  classification cannot misfire on it; the current-tree recording (no marker,
  startup fatal exit) yields the distinct "startup fatal exit" reason.
- **Semantics preserved:** pinned image digest unchanged (byte-identical to
  HEAD), ELF-absent and image-absent SKIP proxies preserved (executed), bounded
  non-hanging run preserved, retained evidence copies preserved, and the
  `RENODE_TEST: PASS` marker criterion unchanged.
- **No forged product output:** the PASS-bearing fixture is the genuine
  recorded 2026-10-20 run; the independent re-execution produced a UART
  console byte-identical to the retained current-run console and a process log
  identical apart from timestamps.

## Residual limits

Host/emulator evidence only: the Renode emulated PolarFire SoC with the
digest-pinned image. **No silicon, no HIL, no target WCET, no hardware-watchdog
claim** — the current N18 FAIL is caused by the target's start-up panic
(NC-EXT-198), not by the tooling. The positive fixture is a recording, not a
re-execution: the current tree cannot reproduce it, because the target panics,
so that fixture's validity depends on the stored artefact remaining
byte-identical. The 120 s wait and the 8 s `.resc` sleep are configuration
values, not a justified worst-case budget. The verdict is a shell unit: no
formal verification and no N10 qualification of these scripts. Fail-closed is
not the same as correct: a FAIL verdict localises neither the product defect
nor its cause.

**Confidence:** high for the confinement, fail-closed, status, classification
and semantics conclusions (source audit plus executed and mutation-verified
cases); the residual Low items are recorded rather than corrected.
