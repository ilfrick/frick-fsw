## 7. FSW-specific review questions

**Q1 — Polled state-machine correctness and the SI-clear discipline.** Verified correct. Each transaction is: `i2c_start` writes `ctrl|STA` (STA set with SI cleared) and polls SI; `i2c_send`/`i2c_begin_read` load DATA **then** clear SI; `i2c_receive` reads DATA **after** SI and clears SI with the correct AA for the *next* byte; `i2c_stop` issues STO. No phase is acted on twice, SI is never cleared twice for one phase, and every error path still issues STOP. The `receive` AA windowing is exactly right: `cap` bytes are read, and **only the final byte is NACKed**. The repeated-START-without-intervening-STOP sequence in `write_read` is correct. **Exception:** STOP completion is not polled (R1-02).

**Q2 — Bounds and determinism.** All loops are statically bounded; no dynamic allocation, recursion, `malloc/free`, `while`, `goto`, delay primitive. Deterministic, allocation-free, single-threaded-callable by design.

**Q3 — Integer and type safety.** Verified; the driver compiles clean under `gcc -std=c11 -Wall -Wextra -Wpedantic -Wconversion -Wsign-conversion -Wshadow -Werror`.

**Q4 — HAL `FF_I2c_t` contract compliance.** Verified against `src/hal/hal_spi.h`; `FF_I2cMpfs_t.i2c` is first; the driver-specific self-test is correctly outside the vtable. No deviation.

**Q5 — Safety / robustness.** NACK → `FF_ERROR` + STOP; stuck SI → `FF_TIMEOUT`; self-test is MMIO-only and safe on a live bus. Not covered: STOP completion (R1-02), arbitration loss (R1-C6), on-target timing (GAP-A5).

**Q6 — Build/test wiring.** Verified; `ctest` 20/20; `test_i2c` 135 checks; `trace.py` PASS with SRS-REQ-058 → SSS-REQ-020.
