## 1. Scope

This is the norm-N20 Product Assurance review of the milestone **M10** increment
that adds the **QEMU leg** of the emulated-target verification path (SRS-REQ-043,
OBJ-18) and declares **M10 closed**. The increment adds a second RTEMS build for
the generic `riscv/rv64imafdc` BSP (`cmake/toolchains/rtems-riscv-generic.cmake`,
`make qemu-image`/`qemu-image-docker`), a binding QEMU check
(`tools/scripts/qemu_vv.sh`, `make qemu`, tool **T20**), extends the RTEMS
toolchain image (`tools/docker/rtems/Dockerfile`, T18) with the `rv64imafdc` BSP
and `qemu-system-misc`, and updates the V&V records, status documents and the
trace manifest. The increment is **uncommitted**: it is a working-tree delta on
top of `aee4135`. Part of this review is therefore to check that the **complete**
product/evidence set intended for the commit is coherent **before** it is
committed (N15, N7, N16, N9/N17/N20).

**Included:** every phase product of the increment (requirements, tooling,
configuration/build, documentation, verification records), the process
obligations it triggers, the factual accuracy of the recorded evidence (banner,
ELF entry, counts, tool register, status/handover statements, README panel), the
traceability convergence for SRS-REQ-043, the honesty/limitation scoping of the
claims (generic BSP; no MPFS peripherals; not silicon), and the specifically
flagged **reproducibility caveat** for the T18 toolchain image.

**Excluded:** the internal correctness adjudication owned by R1 (script/CMake
design) and R2 (V&V method/coverage) — except where a PA-level
records/qualification defect is in scope (where it overlaps, this report adopts
the sibling finding and does not re-derive it); the Lean model (N1 satisfied by
an explicit `lean_note`); R4 documentation adjudication; a Renode re-run (N18 is
unchanged and was verified in the prior cycle); on-target/silicon behaviour
(GAP-A5). This review issues no certification, approval or release statement.

**Method.** Read the full working-tree delta and every in-scope artifact;
independently re-ran the project's local gates read-only (`trace.py`,
`metrics.py --check`, `ctest` on `build/native`); parsed the ELF header of the
QEMU image; sanitised and inspected the recorded QEMU console capture against the
claims; verified the frozen file hashes; searched for the reproducibility caveat
across the repository; inspected the trace mirror, the tool-register evidence
mapping and the CI workflows for the T20 claim; and inspected the
repository/review-log state to determine whether the mandated review evidence
exists at the reviewed revision. The sibling reports **R1 FRICK-REVIEW-0120**,
**R2 FRICK-REVIEW-0121** and **R4 FRICK-REVIEW-0122** (produced in parallel for
this same increment) were read after the fact and are cross-referenced; where
this report reaches the same conclusion it adopts the sibling finding rather than
duplicating the analysis.
