| **R1-01** | **Major** | SRS-REQ-069 — `transfer()` full-duplex RX path | **A stale `RXDATARCVD` / undrained RX FIFO makes the *next* transfer mis-read the received data.** `spi_transfer` never drains the RX FIFO before a transfer and never reads `RXDATA` when `rx == NULL` (`ff_spi_mpfs.c:124`). ## 8. FSW / V&V review questions

**Q1 — Register map and bit positions vs the oracle.** **Match exactly.** Offsets CONTROL `0x00`, FRAMESIZE `0x04`, STATUS `0x08`, INT_CLEAR `0x0C`, RXDATA `0x10`, TXDATA `0x14`, CLKRATE `0x18`, SSEL `0x1C`, INT_MASKED `0x20`, INT_RAW `0x24`, CTRL_ENH `0x28`, CMD `0x2C`, PACKETSIZE `0x30`, CMDSIZE `0x34`, SLAVE_HWSTATUS `0x38`, STATUS8 `0x3C`; CONTROL/STATUS/INT_CLEAR bit positions and the FRAMESIZE/CLKRATE/SSEL masks all match the oracle (STATUS b11 name ambiguous only — R1-C5).

**Q2 — CLKRATE derivation.** **Correct and internally consistent.** `SCL = PCLK/(2·(CLKRATE+1))`; `n = ceil(PCLK/(2·SCL))`, `CLKRATE = n−1`, clamped to `[0,255]`; the `clock_hz >= PCLK/2` early return avoids the `2·clock_hz` overflow; `FF_SPI_MIN_SCL_HZ = 100 MHz/512 = 195312 Hz`. Verified by hand for 1/5/25/40/49.999999/20 MHz, 100 kHz and 1 Hz; all match `test_spi` expectations. The clamp wording is contradictory (R1-C4).

**Q3 — Poll bit and deadlock.** The poll **bit is correct** (STATUS b1 `RXDATARCVD`). It **cannot deadlock**: the loop is bounded by `FF_SPI_POLL_MAX` and returns `FF_TIMEOUT`, and `RXDATARCVD` is a level bit cleared by reading `RXDATA`. It **can mis-read** via a stale `RXDATARCVD` (R1-01, Major).

**Q4 — Bounds, allocation, determinism.** All loops statically bounded (`for` only); no `while`, `goto`, `malloc`/`free`/`calloc`/`realloc`, recursion or delay primitive; deterministic and allocation-free. `FF_STATIC_ASSERT(FF_SPI_MPFS_CLK_HZ > 0u)` present.

**Q5 — Validation and pre-init.** `FF_SpiMpfsSetup` rejects `NULL` `s`/`bus` and either missing bus hook; `init` rejects `clock_hz == 0`, `mode > 3`, `cs > 7`; `transfer` returns `FF_NOT_READY` pre-init; `cs_assert`/`cs_release` reject `cs > 7` but **do not** check readiness (R1-02).

**Q6 — `tx == NULL` / `rx == NULL`.** `tx == NULL` transmits `0x00`; `rx == NULL` discards (does not read `RXDATA`) — the latter is the root of R1-01 and is only partially documented.

**Q7 — Self-test.** Enable via the HAL `init` path, verify CONTROL/CLKRATE/FRAMESIZE and the empty RX FIFO, then re-init; side effects disclosed (`ff_spi_mpfs.h:228-235`). Wording of the second init is imprecise (R1-C3).

**Q8 — HAL contract compliance.** Verified against `src/hal/hal_spi.h`; `FF_Spi_t spi` member; the driver-specific self-test is outside the vtable. No deviation.

**Q9 — V&V evidence.** The mock is a behavioural fake (not an independent oracle) and cannot discriminate a wrong bit (R1-C1); it cannot discriminate the R1-01 fault (R2-01). The Renode check is register round-trips only (correct). `trace.py` PASS with SRS-REQ-069 → SSS-REQ-020; T3 gains `test_spi.c`; T17 gains `hal_spi`; the `ci-renode` markers in both workflows name SRS-REQ-069.

**Q10 — Build/test wiring.** `CMakeLists.txt` adds the driver under `FF_BUILD_DRIVERS`; `tests/CMakeLists.txt` adds `test_spi` + ctest `spi`. Verified 21/21.
