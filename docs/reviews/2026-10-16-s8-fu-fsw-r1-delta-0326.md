## Re-review

1. **Zero-byte read / disconnect — bounded correction accepted.** Source now
   distinguishes a zero-byte result substantially earlier than the configured
   VTIME decisecond from a normal expiry and returns `FF_ERROR` instead of
   retrying. The host PTY test closes the master and checks `FF_ERROR`. The test
   checks status, not a quantitative return-time bound. The elapsed-time
   tolerance is not an RTEMS runtime/timing guarantee.
2. **Ambiguous plausible PDL recovery — remains open.** No inner-boundary
   guessing was added, consistent with the existing requirement to retain a
   plausible incomplete candidate. An in-range malformed candidate can still
   consume bytes that might include a subsequent valid TC. Authorized timeout,
   discard, and recovery policy is needed. NC-EXT-07 remains OPEN.
3. **PTY path — bounded test correction accepted.** `mkdtemp` creates a unique
   per-run directory and the PTY symlink is placed within it, avoiding the
   previous shared deterministic path. A failing run can leave its unique
   directory; cleanup failure is not checked, but cross-run path collision is
   addressed for this host test.

## Limits

No new defect was identified in this focused delta. Host PTY evidence and an
RTEMS cross-build do not establish RTEMS termios timing, target runtime, or
physical UART behavior. This is not a policy, NC-owner, N20 phase, qualification,
or release approval.
