# FRICK-REVIEW-0422 — NC-EXT-197 UART drain-stop synchronization correction

**Profile:** R2 / V&V, fresh independent context  
**Disposition:** Review evidence only. No edits, no NC closure, no gate pass, no
testware qualification, no target WCET claim.

**Scope:** one narrow test-harness correction — the drain thread's stop flag in
`tests/unit/test_link_uart.c` — plus the retained before/after ThreadSanitizer
evidence.

## Conclusion

**The race is resolved and no new defect was introduced.** The stop flag is
accessed under a mutex on every path; no unsynchronized access to shared mutable
state remains in the drain harness; the mutex is initialized before the thread
can touch it and destroyed after the join; the stack-object lifetime and the
bounded drain shutdown are preserved; the correction is confined to one test
file; and the before/after TSan pair is genuine and was independently
reproduced in both directions.

## 1. Synchronization correctness and happens-before

| Location | Access | Under mutex? |
|---|---|---|
| `tests/unit/test_link_uart.c:96` | declaration `bool stop;` | n/a |
| `:307` | initializer `{.stop = false}` (main thread, before `pthread_create`) | ordered by `pthread_create` |
| `:104` | read inside `uart_drain_stopped()` | yes (lock `:103` / unlock `:105`) |
| `:113` | write inside `uart_drain_request_stop()` | yes (lock `:112` / unlock `:114`) |

No direct `drain->stop` access remains. The remaining shared state is ordered
by `pthread_create`/`pthread_join`: `drain->received` is written only by the
drain thread and read by the main thread only after the join; `g_uart_tx_received`
likewise; `drain->target` and `g_master_fd` are written before the thread is
created. The mutex is held for a single `bool` access — no nesting, no lock
inversion, no condition variable, therefore no deadlock path. The stop request
is observed within ≈1 ms because the flag is polled each iteration and the
master descriptor is non-blocking.

## 2. Error-path and thread-lifetime semantics

`pthread_mutex_init` precedes `pthread_create`; `pthread_join` precedes
`pthread_mutex_destroy`; the drain thread is terminated before the enclosing
block ends, so the stack object outlives the thread. `FF_TEST_ASSERT` records
and continues, so an assertion cannot abort the case and leave the mutex
undestroyed on the normal path; the stop request is made before the join, and
the `send_status` assertion follows the join, so a failed send cannot hang the
case.

## 3. Standard conformance

The project requires C99 (`CMAKE_C_STANDARD 99`, `C_STANDARD_REQUIRED ON`,
`C_EXTENSIONS ON` ⇒ `-std=gnu99`). No C11-only construct was introduced: the
only new element is `pthread_mutex_t` from the already-included `<pthread.h>`
(POSIX, not a language-version feature). The file compiles warning-free under
`-std=gnu99 -Wall -Wextra -Werror` and under strict `-std=c99 -pedantic`, and
`tests/CMakeLists.txt` is unchanged, so the `Threads::Threads` linkage is
unchanged. Using pthread synchronization is the right choice for this language
level; the toolchain does accept the C11 atomic builtins as an extension, but
the project must not depend on that, so the rationale in the source comment was
corrected accordingly.

## 6. Findings (all Low; none blocking)

| ID | Finding |
|---|---|
| F-01 | `pthread_mutex_init` failure is recorded but does not gate control flow, so the drain thread could lock an uninitialized mutex. Practically unreachable; **introduced by this fix**. |
| F-02 | On `pthread_create` failure the case continues to `pthread_join` on an uninitialized `pthread_t`. Pre-existing idiom in this file, not introduced here. |
| F-03 | `pthread_mutex_destroy` runs even if the join returned an error (assertions do not gate control flow). Theoretical. |

## 7. Residual limits

Host-only evidence (x86-64, GCC, PTY). No RTEMS, Renode, QEMU, target or HIL
execution; the ≈1 ms stop-poll granularity and the measured wall time are host
properties. The mutex protects only the stop flag; the remaining shared state
relies on the create/join happens-before edges. The drain thread is released
only by a polled flag — no condition variable and no timed join — so a
successful send whose drain does not complete would block in the join until
the CTest timeout converts it into a failure (bounded, pre-existing). The
harness as a whole, including the `--wrap=write` syscall harness, is not
re-qualified by this review.

**Confidence:** high for the synchronization, thread-lifetime and scope
conclusions (source audit plus an independent single-variable TSan reproduction
and an objective manifest check); medium for the environment-dependence
characterization; low only for the unreachable error paths F-01/F-02/F-03, which
are analysed rather than tested.
