## 1. Scope

Reviewed the fifth M11 HAL-coverage increment: **NET exercised in the Renode
functional run** by a socket round trip through the pluggable `FF_NetStack_t`
contract using the reference loopback stack (`FF_NetStackLoopback`,
`hal_net=PASS`), folded into the `RENODE_TEST: PASS` marker.

R1 (design/code) coverage:

- `renode_hal_net_check` (`src/apps/app_renode_test.c:126-166`): argument
  bounds, descriptor lifetimes and `close` on every path, the non-blocking
  `recv` assumption, oracle strength, and the marker conjunction
  (`app_renode_test.c:249-252`).
- Conformance of the exercised sequence to the documented contract
  (`src/hal/hal_net.h`, `docs/architecture/network-stack.md` §2) and to the
  reference implementation (`ff_net_loopback.c`), including whether the check
  is a faithful representative of the *pluggable* contract (address format,
  `attach_netif`) or a loopback-specific smoke test.
- Determinism and the no-dynamic-allocation discipline of the check and the
  driver it drives.

Excluded (other profiles / other scopes): documentation correctness and
revision/history currency (FRICK-REVIEW-0048, R4); independent V&V strategy,
marker AND-logic proof and gate reproducibility (R2); the on-target
lwIP/Ethernet/GEM netif+PHY path (GAP-A5); real-silicon timing.

Assumption recorded: the reviewed artefact is the *uncommitted working tree* on
base `205bfc5`; no committed revision of the NET delta exists yet.

### Empirical evidence (R1) — independently reproduced, not read from the change

**Code correctness / bounds / lifecycle**

- Happy-path lifecycle verified against the real driver with an instrumented
  replica of the check (`/tmp/opencode/netprobe/probe.c`, ASan+UBSan, built from
  the repository sources): `srv=0`, `cli=1`, `acc=2`, all three distinctly
  allocated and closed; `CHECK=1`. Bounds are safe: `buf[8]`/`msg[4]` with a
  4-byte `memcmp`, `peer[8]`/`peer_len=8`, `sent`/`got` are `uint16_t` compared
  against `sizeof` (no truncation).
- `ff_net_loopback.c` compiles and runs clean under
  `gcc -Wall -Wextra -Wpedantic -fsanitize=address,undefined`; the app check
  compiles clean under
  `gcc -Wall -Wextra -Wpedantic -Wconversion -Wsign-conversion -DFRICK_PLATFORM_MPFS -DFF_ENABLE_RENODE_TEST` (no diagnostics).

  (`grep -n 'malloc\|calloc\|free(' src/drivers/net/ff_net_loopback.c src/apps/app_renode_test.c` → none). Static 4-slot
  table (`ff_net_loopback.c:29`, ≈1 KiB). Determinism: the check calls `init()`
  first (`:140`), which resets the table, so repeated invocations are

### Positive evidence

- The check uses the `FF_NetStack_t` **vtable** (`s->init/open/bind/listen/
  connect/accept/send/recv/close`) rather than reaching into the implementation,
  so it does validate that the contract shape works end-to-end on the target —
  a real improvement over the sibling ETH check, which bypasses the HAL.
- The socket lifecycle on the success path is correct and complete (three
  descriptors opened, three closed); the sequence order (`listen` before
  `connect`, `accept` before `send`/`recv`) matches the implementation's
  preconditions.
- Declarations, naming and style are consistent with the rest of
  `app_renode_test.c`; the added comment (`:123-125`) is honest about using the
  "reference loopback stack".
- Determinism and no-alloc discipline are met; the check has no timing
  dependence (the loopback's `recv` is synchronous and non-blocking).
- The `FRICK-REVIEW-0032` R1-01 Major (descriptor guard narrowed by a
  `(uint16_t)` cast) is correctly fixed in the current tree (`sock_of`,
  `ff_net_loopback.c:46-55`), and Comments R1-04/R1-05/R1-06 are addressed.
- `ci:renode` for SRS-REQ-039 is legitimate: the run genuinely executes the
  referenced implementation (verified in the console output and the ELF).

## 4. Conclusion

**R1 (design/code): APPROVED WITH COMMENTS.** No Major finding. The check is
correct and robust in the happy path: it drives the pluggable `FF_NetStack_t`
contract through its vtable on the emulated PolarFire SoC, the socket lifecycle
is sound, the buffers are bounded, `recv` is used in a way consistent with the
loopback's documented non-blocking semantics, and the check is deterministic and
allocation-free. The reproduced target run yields `hal_net=PASS` /
`RENODE_TEST: PASS`.

The residual issues are honesty-of-claim and oracle strength, not correctness:
the check is a loopback-specific software round trip that uses the loopback's
private **1-byte port** address encoding (not the documented 6-octet contract),
never exercises `attach_netif`, and touches no emulated peripheral, yet it is
presented as a "NET HAL class" alongside the peripheral-backed classes
(R1-01); the port-0 oracle cannot detect a `bind` regression (R1-02, proven by
sabotage); the failure paths leak descriptors (R1-03, proven by probe); and the
predecessor Minor NCs on the driver and the missing FRICK-REVIEW-0032 delta
re-review are still open (R1-07). These are Minor/Comments to be corrected or
justified and tracked to closure (N12) before the increment is considered closed.
