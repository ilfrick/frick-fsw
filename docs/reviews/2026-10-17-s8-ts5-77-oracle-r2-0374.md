### 4.1 Mandated sub-questions (a)–(d)

- **(a) Requirement vs implementation-derived expected result.** The four expected behaviours map to the *declared contract*, not to observed implementation: `ff_sched.h` lines 96–104 ("If an absolute target cannot be represented … the entry is disabled until `FF_SchedInit` and `stats.time_exhaustions` increments … `stats.missed` saturates at `UINT32_MAX` … These are provisional framework policies") and ADR-0020 §"Scheduler time exhaustion reference" (checked/non-wrapping arithmetic, fail-closed disable + visible counter, missed counter saturates, no mission action implied). The test does **not** copy the implementation algorithm into the oracle: it asserts observable outcomes (release count, msg_id, `time_exhaustions`, `dispatched`, `missed`) against numeric expectations derived from the policy, at the strict `>` boundary the header states. Grounded and non-tautological.
- **(b) Any time-domain / exhaustion policy asserted beyond ADR-0020.** **No.** All four asserted behaviours correspond to ADR-0020 items: unrepresentable initial deadline → disable + `time_exhaustions`; overflowing subsequent target → no wrap/no re-dispatch; representable deadline at `UINT64_MAX` valid; `missed` saturates at `UINT32_MAX`. The test asserts no restart, reset, safe-state, or recovery behaviour (ADR-0020: "No automatic restart, reset, or mission safe-state action is implied"), and no target timing. `SRS-REQ-071` itself does not define exhaustion/saturation (only allocation-free bounded table dispatch on monotonic time); the test's own header (lines 9–10) and the TS-5 row scope limit both disclaim target/authority claims. Nothing asserted exceeds the provisional framework policy.
- **(c) Overstatement about target timing / schedulability / WCET / recovery.** **None found.** `test_sched.c` lines 9–10 state the results are "host evidence only and does not establish target jitter, WCET or RTEMS behaviour"; the TS-5 `N22-TS5-77` scope limit says "host-only; not an approved mission time domain, operational recovery policy, or target timing result (NC-EXT-90 remains open)"; TS-5 §3.1 residual-limits (lines 248–251) restates the limit under NC-EXT-90. No schedulability, WCET, recovery or mission-domain claim is made.
- **(d) Is the saturating-counter claim actually asserted at the boundary, or only described?** **Asserted, at one boundary.** `test_sched.c` line 338 asserts `st.missed == UINT32_MAX` after a poll whose `skip` exceeds the 32-bit room, which exercises the `skipped >= room` saturation branch in `ff_sched_add_missed`. Mutation testing confirms this assertion has discriminating power (see §4.2). The *exact-hit accumulation* boundary (`skipped == room`, and incremental accumulation across multiple late polls) and the `late_polls` counter increment are not asserted — a completeness observation (F-0374-06, Comment), not an overstatement.
